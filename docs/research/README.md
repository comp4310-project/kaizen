# Research Notes

Literature review, existing-system review, and technical spikes. This directory feeds the
P1 proposal and the related-work sections of later deliverables.

## Layout

- `papers/` — one note per paper read
- `systems/` — reviews of existing tools that solve part of our problem
- `spikes/` — findings from timeboxed technical investigations

## Paper notes

Record, for each paper: the problem it addresses, the method, the data, how it was
evaluated, what it found, its limitations, and — most importantly — what it means for our
design. A note that only summarizes the abstract is not worth writing.

Keep full citations. We will need them, and reconstructing them later is miserable.

## Spikes

A spike answers one question inside a fixed timebox. Write down the question, what you
tried, what you found, and your recommendation. Code written during a spike is throwaway
unless the team explicitly decides otherwise.
